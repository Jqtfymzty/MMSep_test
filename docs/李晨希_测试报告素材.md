## 1. 被测对象与测试范围

本次测试对象为 MMSep 项目中的缓存压缩和视觉 token 筛选功能。李晨希负责的源码范围如下：

| 源码 | 主要测试对象 | 测试重点 |
|---|---|---|
| `src/cache.py` | `MMSepCache` 的历史窗口压缩、分层压缩和 `update()` | 分隔符提取、batch 对齐、缓存拼接、容量边界、prefill/decode 分支和视觉 KV 返回 |
| `src/mm_separators.py` | `graph_rank_separators()` | 视觉 token 排序、原序恢复、mask/位置同步、无图像记录、训练模式、不同长度 batch 和右侧 padding |

测试不调用网络服务，不加载大模型权重，也不依赖 GPU。用例使用小尺寸固定 tensor 和轻量替身对象，使结果可重复并能在普通 CPU 环境快速执行。

## 2. 用例设计

李晨希部分共包含 27 条自动化用例，其中 `cache.py` 相关 17 条，`mm_separators.py` 相关 10 条。用例清单使用了三种测试设计方法：

| 设计方法 | 用例数 | 代表性测试点 |
|---|---:|---|
| 边界值 | 9 | 0 个/1 个分隔符、容量恰好达到上限、最小 decode 增量、无图像记录、可选参数为 `None` |
| 等价类 | 8 | 多个合法分隔符、累积开关、分隔符 token 路径、支持与不支持的注意力类型 |
| 场景法 | 10 | 多 batch 截断或补齐、prefill/decode 更新、视觉 KV 筛选、训练模式、右侧 padding |

三类统计之和为 27，每条用例在 Excel 的“备注”列中标明主要设计方法。完整输入、操作步骤和预期结果见 `docs/李晨希_测试用例清单.xlsx`。

## 3. 自动化测试实现

测试框架采用 pytest，测试代码分布如下：

- `tests/test_cache_compress.py`：17 条缓存压缩测试；
- `tests/test_mm_separators.py`：10 条视觉 token 筛选测试；
- `tests/conftest.py`：提供固定 tensor、缓存对象和模型替身等公共 fixture；
- `run_test.bat`：Windows 环境下一键运行全部测试；
- `README.md`：说明虚拟环境、依赖安装和测试运行方式。

fixture 将重复的准备过程集中管理。例如，多个缓存压缩用例共享固定形状的 Key/Value tensor，测试函数只需突出本用例特有的输入和断言。这样既减少重复代码，也避免不同用例使用不一致的初始数据。

## 5. 缺陷分析

测试过程中共确认并验证 4 项缺陷：

| 缺陷编号 | 缺陷概述 | 修复前现象 | 修复后状态 |
|---|---|---|---|
| B-DEF-01 | 无图像记录访问未初始化的 mask 列表 | `UnboundLocalError` | 目标用例及全量回归通过 |
| B-DEF-02 | 训练模式未给 Query 变量赋值 | `UnboundLocalError` | 目标用例及全量回归通过 |
| B-DEF-03 | 不同视觉长度的 batch 无法堆叠 mask | `RuntimeError` | 输出统一补齐后通过 |
| B-DEF-04 | 右侧 padding 内容干扰视觉 token 排序 | 改变无效 padding 会改变选择位置 | 改用最后有效 token 后通过 |

四项缺陷都经过“修复前历史版本复现—最小范围修改—目标用例验证—27 条用例回归”的过程，不是仅凭源码阅读作出的判断。其中 B-DEF-02 与训练入口是否属于正式支持范围有关，最终报告中应保留“条件性缺陷”的范围说明。

详细复现命令、错误信息和原因分析见 `docs/李晨希_缺陷复现记录.md`，正式缺陷表见 `docs/李晨希_缺陷报告.docx`。

## 6. 测试结论

本轮测试覆盖了缓存压缩的主要正常路径、开关组合和容量边界，也覆盖了视觉 token 筛选中的无图像、训练、多 batch 和 padding 等高风险场景。当前锁定环境下 27 条用例全部通过，4 项缺陷均完成修复验证。

结论的适用范围仅限于本地 CPU 单元测试环境。测试使用小尺寸 tensor 和替身对象，没有验证真实大模型权重、GPU 精度差异、长时间运行性能或完整端到端推理流程，这些内容不应在最终报告中表述为“已经覆盖”。
